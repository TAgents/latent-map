# Base Map v0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a first small map of Inkling 2 Mini's block 2 and block 3 states across the three loop passes, with model-named and scored areas, and decide whether regions are visible.

**Architecture:** A `basemap/` directory next to `spike/`, sharing the spike's virtual environment and its `latent_capture` package. The model writes a small corpus from a topic-by-form grid; one forward pass per text captures every token position; pure numpy/scikit-learn functions fit the projection, cells, layout and areas; the model then names each area and a second run scores the name. Scripts write a bundle, two pictures and a report.

**Tech Stack:** Python 3.12, MLX via the pinned mlx-lm commit, numpy, scikit-learn, umap-learn, matplotlib, pytest.

**Spec:** Technical design https://claude.ai/artifact/7tDZKfqvJvigZij2sT6Dgj, sections "The map" and "Build order" step 2. Ideas behind naming: `research/model-self-visualisation-ideas.md`, `research/goodfire-neuron-atlas.md`.

## Global Constraints

- Model repo `thinkingmachines/Inkling-2-Mini`, loaded with `latent_capture.loader.load_model`.
- Coordinate 2027 is removed before any projection.
- No prompt, text or activation leaves this Mac. No dataset downloads.
- State arrays (`*.npz`, `*.npy`) are git-ignored; the bundle's small JSON files, pictures and report are committed.
- v0 sizes, deliberately below the design's targets: 24 topics x 5 forms = 120 texts, at most 120 generated tokens each; 64 dimensions; 256 cells (design target 4,096); 12 fine areas inside 4 broad areas.
- Random seeds are fixed at 0.
- Commits are local only, on branch `base-map-v0`. Nothing is pushed.

## Rulings made while planning

- **Corpus is model-written, not public text.** The design says "public corpus". v0 uses the model's own text because the corpus choice is an open decision and downloads need licence checks. Cost if wrong: the map sees only what the model writes about 24 topics; the collect step takes any JSONL of texts, so a public corpus drops in later.
- **One cell set per block, pooled over passes, after removing each pass's mean.** The design says "each pass gets its own layout, aligned". Removing per-pass means puts the three passes in one shared layout, which is the simplest form of alignment and lets a word's three passes be drawn on one picture. Cost if wrong: structure that differs by pass in shape, not only in offset, is blurred.

## Go thresholds (set before seeing data)

"Regions are visible" means all three hold for at least one of block 2 or block 3:

- **Form lift >= 1.5:** mean share of the commonest text form within a fine area, divided by the share of the commonest form overall.
- **Topic lift >= 1.5:** the same for topic.
- **Mean name score >= 0.5** with four options (chance 0.25).

## Review Focus

- A text shorter than expected or an empty generation: collection must skip it and say so, not crash.
- An area with too few distinct words to name: naming must return an empty name with score 0, not an invented one.
- The model answering the scoring question with something other than A to D: counted as wrong, never as a crash.
- Cells with no points after assignment: areas, words and drawing must tolerate empty cells.
- Per-pass mean removal applied to new points with the stored means, not recomputed from the new points.

### Task 4: Fit the map and group areas

**Files:**
- Create: `basemap/mapbuild/fit.py`, `basemap/mapbuild/areas.py`, `basemap/build_map.py`
- Test: `basemap/tests/test_fit.py`, `basemap/tests/test_areas.py`

**Interfaces:**
- Produces, `fit.py`:
  - `fit_map(states: np.ndarray, dims=64, cells=256, drop=2027, seed=0) -> dict` — `states` is `(N, passes, d)`. Returns `drop: int`, `pass_means: (passes, d-1)`, `components: (dims, d-1)`, `centres: (cells, dims)`, `xy: (cells, 2)`. Steps: delete coordinate `drop`, unit-normalise each vector, subtract each pass's mean, PCA on the pooled points, k-means, UMAP of the centres. `dims` and `cells` are clipped to what the data allows.
  - `place(m: dict, states: np.ndarray) -> np.ndarray` — `(N, passes)` int cell ids, using the stored means.
- Produces, `areas.py`:
  - `group_cells(centres, n_fine=12, n_broad=4) -> tuple[np.ndarray, np.ndarray]` — fine and broad area id per cell from one Ward linkage tree, so every fine area lies inside exactly one broad area.
  - `distinctive_words(tokens: list[str], area_of_point: np.ndarray, top=12, min_count=3) -> dict[int, list[str]]` — per area, words ranked by share inside the area minus share overall; tokens are stripped and lowercased, and tokens with no letters are ignored. An area with no qualifying words maps to `[]`.
  - `lift(area_of_point: np.ndarray, labels: list[str]) -> float` — the go-threshold statistic.
- `build_map.py` writes, for each of `block2` and `block3`: `basemap/bundle_v0/<block>.npz` (the `fit_map` arrays plus `fine`, `broad`, and `cell: (N, passes)`) and `basemap/bundle_v0/<block>.json` (`words` per fine area, `form_lift`, `topic_lift`, `occupied_cells`). Areas and lifts are computed on reply tokens at pass 3.

def blobs(seed=0):
    r = np.random.default_rng(seed)
    cents = r.normal(size=(4, 40)) * 4
    lab = np.repeat(np.arange(4), 60)
    x = cents[lab][:, None, :] + r.normal(size=(240, 3, 40)) * 0.3
    x += np.array([0.0, 5.0, 10.0])[None, :, None]  # a per-pass offset to be removed
    return x, lab

def test_fit_map_shapes_and_clipping():
    x, _ = blobs()
    m = fit_map(x, dims=64, cells=16, drop=7)
    assert m["components"].shape == (39, 39) and m["centres"].shape == (16, 39) and m["xy"].shape == (16, 2)

def test_place_separates_blobs_and_ignores_pass_offset():
    x, lab = blobs()
    m = fit_map(x, dims=8, cells=4, drop=7)
    c = place(m, x)
    assert c.shape == (240, 3)
    assert (c[:, 0] == c[:, 2]).mean() > 0.95           # same blob lands in the same cell on every pass

### Task 5: Model-named areas, pictures and report

**Files:**
- Create: `basemap/mapbuild/naming.py`, `basemap/name_areas.py`, `basemap/draw_map.py`, `basemap/REPORT.md`
- Test: `basemap/tests/test_naming.py`

**Interfaces:**
- Produces, `naming.py` (`ask` is any `Callable[[str], str]`, so tests use fakes):
  - `name_area(ask, words: list[str]) -> str` — empty string when `words` has fewer than 3 items; otherwise the first line of the reply, stripped of quotes and trailing punctuation, cut to 6 words.
  - `score_name(ask, name: str, own: list[str], others: list[list[str]], trials=4, seed=0) -> float` — each trial shows the name and four lettered word lists (the area's own held-out words and three other areas'), shuffled; the score is the share of trials whose reply starts with the right letter. Empty name scores 0.0. Fewer than three other areas with words: uses what there is.
- `name_areas.py`: for each block, names every fine area from the first half of its distinctive words (use `top=16`) and scores on the second half; names each broad area from its fine areas' names. Updates `bundle_v0/<block>.json` with `names`, `name_scores`, `broad_names`, `mean_name_score`. A name scoring below 0.5 is stored but flagged `"weak": true`, and drawn as "part of <broad name>".
- `draw_map.py`: writes `basemap/bundle_v0/<block>.png`: cells at `xy`, sized by reply-token count at pass 3, coloured by fine area, labelled with names; and `basemap/bundle_v0/passes.png`: the same layout three times, one per pass, coloured by the share of each cell's points whose cell differs from its pass-3 cell.
- `REPORT.md`: the three go thresholds against measured values per block, the verdict, both pictures, the area names with scores and words, what was not tested.
